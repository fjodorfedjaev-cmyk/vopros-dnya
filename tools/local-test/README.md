# Локальная проверка онлайн-функций (без живых людей и без рабочей базы)

Здесь всё, чтобы перед выкладкой прогнать новую онлайн-функцию так, как будто играют несколько человек:
локальный Postgres с заглушками рабочей базы + весь сайт в браузере (Chrome без окна) + «игроки»-скрипты.
Рабочую базу Supabase это не трогает.

## Что здесь лежит

| Файл | Что делает |
|---|---|
| `stub.sql` | Заглушки того, на что опираются миграции и сайт: `profiles`, `admins`, `is_member()`, `is_admin()`, книга монет, `coins_of`, `my_points`, `member_coins`, `push_call` (вместо отправки пишет в `push_calls`). Шесть выдуманных участников, первый — админ, у каждого 1000 монет. |
| `db.sh` | Поднимает Postgres (порт 5433) и создаёт базу заново: `./db.sh ИМЯ stub + миграции…` |
| `server.js` | Раздаёт файлы сайта на `http://localhost:8099` и выполняет вызовы базы в локальном Postgres от имени «вошедшего». |
| `shim.js` | Поддельный supabase-js: подставляется в браузер вместо настоящего. Вызовы из `LOCAL_RPC` идут в локальную базу, остальное — пустые ответы (сайт при этом загружается). |
| `browser.js` | Общие шаги: открыть сайт «телефоном» от имени участника, зайти в «Дурака», сделать ход. |
| `durak-players.js` | 2–5 живых игроков играют партию через весь сайт; `--afk` — последний не ходит. |
| `durak-bots.js` | Админ открывает тестовую комнату и играет против ботов; проверяет, что другу её не видно. |
| `poker-bots.js` | «Покер»: админ открывает тестовый стол, сажает 1–5 ботов, играет раздачи (повышения ползунком, докупка, «Встать»); монеты админа не меняются. |
| `poker-players.js` | «Покер»: 2–6 живых игроков за одним столом через весь сайт; в конце все встают — монеты всех сходятся до копейки. |

## Как запустить (Claude делает это сам перед выкладкой)

```bash
cd tools/local-test
./db.sh e2e ../../supabase/durak/01_durak.sql ../../supabase/durak/02_bots.sql   # база: заглушки + миграции (без тестов!)
DB=e2e node server.js &                                                          # сайт на localhost:8099
node durak-players.js 3          # трое живых
node durak-players.js 5 --afk    # пятеро, один не ходит — проверка времени и выбывания
node durak-bots.js 3             # админ против трёх ботов
```

«Покер» (база — те же миграции «Дурака» и `../../supabase/poker/01_poker.sql`):

```bash
./db.sh e2e ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql
node poker-bots.js 5 6           # админ против пяти ботов, 6 раздач
node poker-players.js 6 4        # шестеро живых, 4 раздачи
```

Скриншоты — в `shots/` (в git не попадают). Скрипт завершается с ошибкой, если партия не закончилась
или на страницах были ошибки JavaScript.

Тест базы (SQL с откатом) — так же на локальной базе, перед тем как запускать его на рабочей:

```bash
./db.sh t ../../supabase/durak/01_durak.sql ../../supabase/durak/02_bots.sql
psql -h /tmp -p 5433 -U postgres -d t -1 -f ../../supabase/durak/99_test.sql
```

«Покер»: `./db.sh t ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql`, потом `99_test.sql` и `99_bots_test.sql` из `supabase/poker/`.

## Для новой онлайн-функции

1. Если миграция опирается на то, чего нет в `stub.sql`, — добавить туда заглушку (только устройство, без данных).
2. В `shim.js` добавить её вызовы в `LOCAL_RPC` (и в `SETS` в `server.js`, если функция возвращает таблицу).
3. Написать сценарий по образцу `durak-players.js`: несколько «телефонов», каждый от своего участника.

## Боты на настоящем сайте

Для проверки самому, с телефона: «Карты» → «Китайский дурак» → «Новая комната» → «Тестовая, с ботами» (кнопку видит только админ).
В «Покере» так же: «Карты» → «Покер» → «Новый стол» → «Тестовый, с ботами», за столом кнопка «+ бот» (до 5 ботов).
Комната видна только админу, без ставки и уведомлений; «Добавить бота» — до 4 ботов. Боты ходят сами
через 1,5 секунды после начала своего хода. Ботов нет в «Участниках», рейтингах и статистике — у них нет профиля.

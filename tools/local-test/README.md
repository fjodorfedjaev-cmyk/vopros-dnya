# Локальная проверка онлайн-функций (без живых людей и без рабочей базы)

Здесь всё, чтобы перед выкладкой прогнать новую онлайн-функцию так, как будто играют несколько человек:
локальный Postgres с заглушками рабочей базы + весь сайт в браузере (Chrome без окна) + «игроки»-скрипты.
Рабочую базу Supabase это не трогает.

## Что здесь лежит

| Файл | Что делает |
|---|---|
| `stub.sql` | Заглушки того, на что опираются миграции и сайт: `profiles`, `admins`, `is_member()`, `is_admin()`, книга монет, `coins_of`, `my_points`, `member_coins`, `push_call` (вместо отправки пишет в `push_calls`). Шесть выдуманных участников, первый — админ, у каждого 1000 монет. |
| `db.sh` | Поднимает Postgres (порт 5433) и создаёт базу заново: `./db.sh ИМЯ stub + миграции…` |
| `server.js` | Раздаёт файлы сайта на `http://localhost:8099` и выполняет вызовы базы в локальном Postgres от имени «вошедшего». |
| `shim.js` | Поддельный supabase-js: подставляется в браузер вместо настоящего. Вызовы из `LOCAL_RPC` идут в локальную базу, остальное — пустые ответы (сайт при этом загружается) или то, что положено в localStorage `mock-rpc` / `mock-tables`. |
| `browser.js` | Общие шаги: открыть сайт «телефоном» от имени участника, зайти в «Дурака», сделать ход. |
| `durak-players.js` | 2–5 живых игроков играют партию через весь сайт; `--afk` — последний не ходит. |
| `durak-bots.js` | Админ открывает тестовую комнату и играет против ботов; проверяет, что другу её не видно. |
| `poker-bots.js` | «Покер»: админ открывает тестовый стол, сажает 1–5 ботов, играет раздачи (повышения ползунком, докупка, «Встать»); монеты админа не меняются. |
| `poker-players.js` | «Покер»: 2–6 живых игроков за одним столом через весь сайт; в конце все встают — монеты всех сходятся до копейки. |
| `poker-combo.js` | «Покер»: подсказка лучшей комбинации (`bestHand` из `poker.js`) против базы (`poker_eval` / `poker_name`) на тысячах случайных наборов из 2–7 карт: название, карты комбинации, достоинства. `node poker-combo.js 20000`. |
| `poker-combo-ui.js` | «Покер»: подсветка на экране — стол ставится в нужное положение прямо в базе: две пары и стрит с тузом снизу в раздаче, после паса — пусто, вскрытие с победой бота (подсвечен победитель, моё название серое), флеш из шести черв. |
| `cards-stub.sql` | Дополнительные заглушки для «Коллекции» и «Лавки» (`auth.users`, `suggestions`). Ставится сразу после `stub.sql`. |
| `market-bids.js` | «Лавка: рынок и заявки» — продавец и покупатель через весь сайт: каталог мини-квадратиками, сортировка, коллекция и редкость, метки фильтров, страница карточки, заявка (монеты откладываются), «Продать сразу», покупка выбранного номера, заявка дороже лота — «Купить сразу», «Мои сделки», отмена заявки; монеты сходятся. |
| `suggest-kinds.js` | «Свой вопрос» по видам: в очереди админа и в «Моих предложениях» — только выбранный вид (Вопрос / Слово / Выбор), цифры на переключателе и на кнопке «Предложить», поля не растягиваются рукой и сами растут под текст. Данные — через localStorage `mock-rpc`. |
| `people.js` | «Мини-профиль»: из Участников — окно с аватаркой, знаком, «с нами с …», «сегодня», плитками, витриной (карточка крупно), играми и счётом ваших дуэлей; свой профиль; «Вызвать на дуэль» → Сектор с выбранным человеком; имя в ленте ответов и у продавца в Лавке. |
| `profile-stub.sql`, `profile-seed.sql` | Заглушки для мини-профиля (ответы, реакции, комментарии, `member_stats`, сессии Сектора и Зигзага) и данные для проверки (серия, рекорды, дуэли, витрина друга). |
| `coll-redesign.js` | «Коллекция»: блок открытия, «Что может выпасть», открытие по нажатиям и экран результата, «На витрину», альбом (фильтры, «Новая», силуэты), панель карточки снизу, перетаскивание на витрину, витрина в Профиле, выбор карточки в «Лавке». Нужна свежая база. |

## Как запустить (Claude делает это сам перед выкладкой)

```bash
cd tools/local-test
./db.sh e2e ../../supabase/durak/01_durak.sql ../../supabase/durak/02_bots.sql   # база: заглушки + миграции (без тестов!)
DB=e2e node server.js &                                                          # сайт на localhost:8099
node durak-players.js 3          # трое живых
node durak-players.js 5 --afk    # пятеро, один не ходит — проверка времени и выбывания
node durak-bots.js 3             # админ против трёх ботов
```

«Покер» (база — те же миграции «Дурака» и `../../supabase/poker/01_poker.sql`):

```bash
./db.sh e2e ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql
node poker-bots.js 5 6           # админ против пяти ботов, 6 раздач
node poker-players.js 6 4        # шестеро живых, 4 раздачи
```

«Коллекция» и всё сразу (одна база на все сценарии; `DB=` у сценариев должен совпадать с базой сервера):

```bash
./db.sh coll cards-stub.sql ../../supabase/cards/01_cards.sql ../../supabase/market/01_market.sql \
  ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql ../../supabase/poker/02_play_money.sql ../../supabase/market/02_bids.sql
psql -h /tmp -p 5433 -U postgres -d coll -c "insert into public.points_ledger (user_id, amount, reason, ref) select id, 5000 - public.coins_of(id)::int, 'game', 'test:coins' from public.profiles"
DB=coll node server.js &
DB=coll node coll-redesign.js
DB=coll node market-bids.js      # на свежей базе
```

Мини-профиль (база `pf`):

```bash
./db.sh pf cards-stub.sql profile-stub.sql ../../supabase/cards/01_cards.sql ../../supabase/market/01_market.sql \
  ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql ../../supabase/poker/02_play_money.sql \
  ../../supabase/market/02_bids.sql ../../supabase/duels/01_duels.sql ../../supabase/members/02_member_profile.sql
psql -h /tmp -p 5433 -U postgres -d pf -f profile-seed.sql
DB=pf node server.js &
DB=pf node people.js
psql -h /tmp -p 5433 -U postgres -d pf -f ../../supabase/members/99_profile_test.sql   # тест базы (сам откатывается)
```

Тест заявок (SQL с откатом): на базе `t` с теми же миграциями — `psql … -d t -f ../../supabase/market/99_bids_test.sql`.
Старый тест лавки `market/99_test.sql` локально требует заглушек `push_hook_secret()`, `net.http_request_queue` и пропуска шага 16 (предложения).

`shim.js` отправляет в локальную базу и вызовы `cards_…`/`market_…`, поэтому для «Коллекции» и «Профиля»
в базе должны быть миграции карточек и Лавки (как выше). Сценарии «Дурака» оставляют за собой начатую игру —
перед следующим сценарием базу лучше пересоздать.

Скриншоты — в `shots/` (в git не попадают). Скрипт завершается с ошибкой, если партия не закончилась
или на страницах были ошибки JavaScript.

Тест базы (SQL с откатом) — так же на локальной базе, перед тем как запускать его на рабочей:

```bash
./db.sh t ../../supabase/durak/01_durak.sql ../../supabase/durak/02_bots.sql
psql -h /tmp -p 5433 -U postgres -d t -1 -f ../../supabase/durak/99_test.sql
```

«Покер»: `./db.sh t ../../supabase/durak/0[1-6]*.sql ../../supabase/poker/01_poker.sql`, потом `99_test.sql` и `99_bots_test.sql` из `supabase/poker/`.

## Для новой онлайн-функции

1. Если миграция опирается на то, чего нет в `stub.sql`, — добавить туда заглушку (только устройство, без данных).
2. В `shim.js` добавить её вызовы в `LOCAL_RPC` (и в `SETS` в `server.js`, если функция возвращает таблицу).
3. Написать сценарий по образцу `durak-players.js`: несколько «телефонов», каждый от своего участника.

## Боты на настоящем сайте

Для проверки самому, с телефона: «Карты» → «Китайский дурак» → «Новая комната» → «Тестовая, с ботами» (кнопку видит только админ).
В «Покере» так же: «Карты» → «Покер» → «Новый стол» → «Тестовый, с ботами», за столом кнопка «+ бот» (до 5 ботов).
Комната видна только админу, без ставки и уведомлений; «Добавить бота» — до 4 ботов. Боты ходят сами
через 1,5 секунды после начала своего хода. Ботов нет в «Участниках», рейтингах и статистике — у них нет профиля.
